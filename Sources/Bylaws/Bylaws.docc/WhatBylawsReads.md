# What Bylaws reads

Choose a source query or compiler-index query for the information your rule
needs.

## Overview

You can check declarations, imports and calls before a build. For references
or conformances resolved by the compiler, use an index query after building
the relevant targets.

File and codebase queries include global declarations, type members and nested
types. They do not include local variables, local functions or local types
declared inside a function body. Body-level calls remain available through the
enclosing function, initialiser or property.

| The rule needs | Use |
| --- | --- |
| Written declarations, imports, types or calls | The `Codebase` query model |
| Cyclomatic complexity | `Function.cyclomaticComplexity` or `Initializer.cyclomaticComplexity` |
| Other control flow, local syntax or comment trivia | `withSyntax` |
| Resolved definitions, references or conformances | The `BylawsIndex` product |

## Every branch of an `#if` is read

A source query checks declarations in every `#if` branch, including those for
other platforms. For example, a macOS run includes this import even though the
compiler excludes it from the macOS build:

```swift
#if os(Linux)
import Glibc
#endif
```

You can check a convention such as "every class is final" across platforms in
one run, including code inside `#if false`. To exclude platform-specific code
from a rule, keep it in separate files and filter by path:

```swift
let app = Codebase(
    including: ["Sources/**"],
    excluding: ["**/*+Linux.swift"]
)
```

## Written types

`hasType("Repository")` matches an explicit `: Repository` annotation. To
also find properties such as `let store = Repository()`, include a call check:

```swift
let violations = try await Codebase.app.properties
    .violations(matching: .hasType("Repository") || .calls("Repository"))
```

The call check matches the written name `Repository` rather than inferring the
property's type. Queries cannot determine inferred closure parameter types
either. For a `some` return type, they provide the written constraint rather
than the concrete type chosen by the compiler.

## Written names

If two selected modules both declare `Client`, a name filter matches both.
Source queries can follow inheritance, conformances and typealiases through
the declarations included in the codebase. They stop at a type whose
declaration is outside that selection.

For example, a source query can find a `Codable` conformance added by an
extension in a local package if you include that package's source files.

## Macro uses

You can check where code uses `@Observable` or `#Preview`, but the queries read
the macro invocations without expanding them. Declarations generated by a macro
are outside the source model.

## Swift source files

Bylaws checks `.swift` files, so you need another analysis tool for declarations
that exist only in an Objective-C header.

## Control flow

Use `cyclomaticComplexity` to count branches in a function or initialiser.
The count includes `if` and `switch` expressions and `for await` loops.

For other control-flow rules, use `withSyntax` to inspect the syntax tree.
For example, you can require a `switch` to name every case as shown in
<doc:AdvancedRules#Reach-the-syntax-tree>.

## Comments are trivia

A documentation comment appears in the model as
``/BylawsSemantics/Documented/documentation``. For another comment, such as a
`TODO` marker or a licence note, read the syntax trivia with `withSyntax`. A
search of the declaration's source text is less exact because it also matches
string literals and identifiers.

## When you need the compiler

After building the relevant targets, you can use `BylawsIndex` to find a
symbol's definition, references and protocol conformances in the compiler's
index. The results describe that build's modules and active `#if` branches,
so rebuild when those inputs change.
