# swift-format rule coverage

This audit covers swiftlang/swift-format 604.0.0, released on 16 September 2026. It uses commit [`15d7877`](https://github.com/swiftlang/swift-format/commit/15d7877c6b32926948f6520f0156657945955ea3) and was checked on 23 October 2026. This is the Swift project tool, distinct from nicklockwood/SwiftFormat.

The inventory includes every registered rule, every configuration key and the pretty printer findings. It also records every syntax handler in the pinned pretty printer. The classifications describe the API work a rule author faces. They do not establish output parity with upstream.

## How to read the tables

| Classification | Meaning |
| --- | --- |
| direct | An existing captured-source query and layout operation express this policy. |
| source-edit | A captured text or whitespace replacement can express the policy. The author supplies the matching and replacement logic. |
| native-syntax | The full behaviour needs SwiftSyntax traversal or transformation in a native Swift Testing rule. The portable API lacks part of the structure or policy. |
| diagnostic-only | Upstream reports the issue without an automatic correction. The note states what the check needs. |
| semantic | The rule needs compiler information or a proof beyond syntax. No upstream rule in this inventory uses this classification. |
| unsupported | The API has no equivalent policy. Whole-file replacement could host a custom implementation, but that does not make the policy easy to express. |

A direct classification applies to a policy, not every upstream edge case. The existing layout tests cover selected attributes, statements, properties and comma-separated lists. No row in this audit has an upstream conformance test. In particular, a native syntax escape hatch is a possible implementation route, not evidence of a small or portable rule.

| Syntax family | Assessment |
| --- | --- |
| Declarations, bodies and accessors | Captured member, statement, attribute, modifier, parameter and accessor lists cover local arrangements. Empty bodies, effect specifiers and whole-signature break priorities need extra policy. |
| Conditions, generic clauses, inheritance and associated types | Captured conditions, generic parameters, generic arguments, requirements, inherited types and primary associated types support local list layouts. Type constraints and individual token spelling remain rule logic. |
| Calls, subscripts, tuples, collections and closures | Captured expression, tuple type, tuple pattern, capture, closure parameter and enum associated-value lists support local layouts. Full parity also needs trailing-closure rules and contextual breaks across nested expressions. |
| Control flow and switch cases | Captured switch cases and case patterns support local layouts. Tokens expose catch and else boundaries. Case labels can use the switch as their indentation base. Conditional-compilation indentation needs additional policy. |
| Operators, casts, patterns and expression chains | Precedence, token adjacency and contextual breaks need syntax-aware matching. Range operators can use a custom precedence group. Adjacent prefix or postfix operators can make space removal change parsing. |
| Types, packs, macros and attribute arguments | Each syntax form has its own punctuation and spacing. A native implementation must also use a SwiftSyntax version that can parse that form. |

## Gaps and validation

This change adds captured token and trivia queries, edit composition and canonical list projections. List indentation uses the enclosing source as its base. The unit comes from source outside the replaced list, so the replacement cannot increase that unit on a later run. When no surrounding space indentation is available, the unit is two spaces. Tabs use one tab per level. The remaining shared gaps are an explicit indentation-unit choice, configurable tab width, declarative separator changes and contextual wrapping across a whole signature or expression chain.

The layout builder preserves the captured elements exactly once. A canonical element's source includes its trailing comma, when present. A nested layout edit must target the content before that separator. Several upstream rules create, delete or split syntax, so preserving the layout inventory is not a substitute for a transformation API. Renames and changes to optional handling also need a policy for their effect on other code.
